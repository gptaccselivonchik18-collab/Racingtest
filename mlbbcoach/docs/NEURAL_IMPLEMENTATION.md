# Нейросетевое ядро: границы и проверка

## Аудит исходной версии

Настоящие модели: Apple Foundation Models для чата/разбора, Vision OCR и импортируемая Core ML-модель для записей. Живой HP — эвристический датчик полосы либо OCR, два согласованных наблюдения и пороги 15/30%; стратегических нейросетевых решений там не было. Память сохраняла текст без изменения весов. Обученного MLBB-детектора, собственного языкового runtime, анализа карты и драфта не было. Живой поток получает настоящие SCStream-буферы; физическая работа ещё не подтверждена отчётом iPhone. Демонстрационные кадры в рабочем потоке не используются.

## Реализовано в коде

- Маленькая нейросеть 768 → 24 tanh → N softmax, cross-entropy SGD/backpropagation на CPU. Исходные и новые массивы весов сравниваются. Это настоящее обучение нейросети, не память/RAG и не обновление языковой модели.
- Импорт скриншота, ручная область иконки, код класса и русское название, группа матча и разделение train/validation. Сохраняются crop PNG, признаки, разметка и SHA исходного скриншота. Один скриншот/группа не допускаются в обе выборки; одинаковые признаки не дублируются. Минимум 3 train и 2 validation на класс, 2–32 класса, до 500 примеров.
- Кандидат обучается вне захвата, сравнивается на одной и той же отложенной выборке, сохраняет before/after accuracy/loss и факт изменения весов. Активация только при accuracy >= 70%, отсутствии ухудшения accuracy и снижении loss. Смена набора классов не заменяет старую модель автоматически. Есть сохранение активных/предыдущих параметров и откат.
- Живой процессор запускает тот же классификатор в заданных областях раз в 3 секунды; требуется score >= .85 и два согласованных наблюдения. Это не калиброванная вероятность и не универсальный детектор. Стороны и области задаёт пользователь. Без размеченных данных активной модели нет; предсказания не используются как обучающие метки.
- Распознанные иконки и HP поступают в структурированное состояние и реальную языковую модель, сравнивающую 2–5 альтернатив с порядковыми оценками полезности/риска. Старый HP-канал срочных предупреждений сохранён. Позиции, золото, навыки, намерения и статистика патча отмечены неизвестными.
- Apple получает только контролируемый английский JSON и английские Generable-схемы/инструкции. Свободный русский ввод, память и OCR не попадают в Apple-путь. supportsLocale(en_US) и обработка unsupportedLanguageOrLocale для iOS 26/27 сохранены. Ответ — типизированные действия/основания, преобразуемые локально в русский текст без запроса к переводчику.
- Независимый llama.cpp b5046 (официальный XCFramework, проверенный SHA-256), CPU, 2 потока, 2048 токенов, ограниченные генерация/отмена. Импорт GGUF с SHA-256 и загрузка официального Qwen2.5 1.5B Instruct Q4_K_M с фиксированной ревизией/хешем. Русский чат работает через этот runtime. Языковая модель выбирается пользователем; платных API нет.
- Фоновая глубокая стратегия запускается только CPU-runtime и по событиям не чаще 25 секунд. Apple-путь доступен для анализа последнего состояния в приложении: право захвата не принимается за право фоновой GPU-генерации. Перед доставкой сверяется свежесть и неизменность доступных полей состояния. Работа во время MLBB должна проверяться на iPhone.

## Автоматическая проверка

См. актуальный GitHub Actions run. Эксперимент обучения использует явно синтетические векторы, проверяет реальные изменения весов, held-out loss/accuracy, сериализацию и восстановление предыдущих весов. Это доказательство механизма обучения, а не точности на MLBB. Отдельное задание загружает проверенный настоящий Qwen и запускает CPU inference с русским ответом на macOS. Это не измерение скорости iPhone или качества стратегии.

## Проверка на настоящем iPhone — ещё не проведена

1. Импортировать скриншоты MLBB из разных матчей. Разметить минимум 2 героя, отдельно train и validation. Не использовать соседние кадры одного матча как независимую проверку.
2. Обучить. Сохранить метрики и UUID активной версии, перезапустить приложение, проверить UUID, выполнить откат после второй успешной версии. Новая точность может не улучшиться — кандидат должен остаться неактивным.
3. Задать области иконок на горизонтальном кадре. Запустить захват MLBB. Сверить реальные предсказания и ошибочные срабатывания; сохранить журнал. Нужна отдельная независимая тестовая выборка, не использованная для выбора версии, чтобы оценить обобщение.
4. Скачать GGUF, включить его, проверить русский чат без сети, сравнение альтернатив и живую стратегию. Проверить звук/баннеры, свежесть, CPU-нагрузку, нагрев и задержки. Экспортировать LiveDiagnostics.json и AdviceJournal.json.

## Пока не реализовано / не подтверждено

Нет обученной поставляемой модели героев или тестов на настоящих изображениях MLBB: пользовательские данные ещё не получены. Нет полноценного распознавания миникарты, предметов, объектов, умений, автоматического определения сторон, анализа контрпиков/синергии, подтверждённой базы характеристик текущего патча, специализированной обучаемой модели действий, автоматического обучения по исходам матчей и доказанного автономного улучшения. Эти функции не считаются выполненными. Ограниченный state не позволяет обоснованно решать все перечисленные стратегические задачи.
